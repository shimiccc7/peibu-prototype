# Product contract · first prototype

## Target hypothesis

A parent of one elementary-age child who has schoolwork and music practice, and needs to adapt daily arrangements without rewriting the whole plan. This is a validation hypothesis, not a proven market or learning-efficacy claim.

## Core loop

Set one weekly goal → inspect today’s next small step → record done / help / rest → adjust future flexible blocks with a preview → reuse a workable week.

## Acceptance scenarios

1. A new family can change nickname, daily availability, tasks and quantities without editing code.
2. A child sees a readable next action, not a whole-week score or parent administration table.
3. Finishing a task, changing the mode and undoing that change never erase the fact.
4. Required work and fixed activities remain visible when a day becomes a rest day.
5. A new week created from a template never looks already completed.
6. Unknown real time/quantity remains unknown.
7. The parent sees storage failure or schedule conflict rather than false success.

## Not promised

Improved musical performance, optimized learning dosage, medical/psychological recommendations, AI assessment, data synchronization, notifications, or fully autonomous scheduling. Sample practice instructions are generic demo copy and not a replacement for the child’s actual teacher.

## Pilot limits

One profile per browser, a small dataset under 1 MB, fictional or non-sensitive entries only. No login, remote users or payments. Test the interaction with adults before allowing children to use it unsupervised.
